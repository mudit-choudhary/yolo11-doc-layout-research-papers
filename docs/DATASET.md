# Dataset

How the training data was built, why it looks the way it does, and how to
rebuild it. None of the data itself is in git; this document is what stands in
for it.

## What exists

| Directory | Size | In git |
|---|---|---|
| `PDFs/` | 4.4 GB | No |
| `images/` | 19 GB | No |
| `training_dataset/*/images`, `labels` | 1.4 GB | No |
| `training_dataset/*/data.yaml`, `classes.txt` | KB | **Yes** |
| `training_dataset/*/{train,val,test}.txt` | KB | No, derived |

The configs are tracked because they are decisions. The split lists are not,
because they are regenerated by one command and contain machine-specific
absolute paths.

## The 12 classes

| ID | Class | Notes |
|---|---|---|
| 0 | Caption | Figure and table captions |
| 1 | Footnote | Bottom-of-page notes, not page furniture |
| 2 | Formula | Display equations |
| 3 | List-item | One box per item |
| 4 | Page-footer | Page numbers, conference footers |
| 5 | Page-header | Running heads |
| 6 | Picture | Figures, plots, diagrams |
| 7 | Section-header | Numbered and unnumbered headings |
| 8 | Table | The table body |
| 9 | Text | Body paragraphs |
| 10 | Title | Paper title, first page |
| 11 | Authors | **Custom.** Author block and affiliations |

The first eleven are inherited from the DocLayNet-style base checkpoint.
`Authors` was added because research-paper front matter has no equivalent in
that taxonomy, and separating it from `Text` matters for citation handling
downstream.

**Order is load-bearing.** YOLO label files reference classes by integer index
alone, so `classes.txt`, the `names:` block of every `data.yaml`, and
`CLASS_NAMES` in `doclayout_ft/config.py` must agree exactly. A test enforces
the last two against each other.

## Rebuilding from scratch

### 1. Source PDFs

The corpus is 1128 arXiv preprints, skewed toward machine learning, retrieval
and systems papers. The specific papers are not special. Any comparable set of
two-column English preprints will do.

Only a fraction has been annotated. 1128 PDFs render to roughly 22,000 page
images, of which 850 are labelled and in `round_final`. The rest of the pool is
there so later annotation rounds have material to draw on.

arXiv's [bulk access](https://info.arxiv.org/help/bulk_data.html) is the
polite route for a corpus this size. Do not scrape the website: it is rate
limited, and the bulk endpoints exist precisely for this.

For a smaller set, the [arXiv API](https://info.arxiv.org/help/api/index.html)
serves metadata and PDF links, with a courtesy delay of about three seconds
between requests.

Whichever route, drop the PDFs flat into `PDFs/`. The filename becomes the
paper identity used for grouping later, so keep it stable and free of
`_page_NN`.

### 2. Render pages

```bash
python -m doclayout_ft.data.pdf_to_images
```

300 DPI JPEG, one file per page, named `<PaperName>_page_NN.jpg`. Roughly five
hours for 1128 papers, producing about 22,000 pages and 19 GB.

### 3. Batch and annotate

```bash
python -m doclayout_ft.data.make_batches --batch-name batch_01
```

Annotated by hand in [X-AnyLabeling](https://github.com/CVHub520/X-AnyLabeling),
run in Docker, exported as YOLO horizontal bounding boxes.

Batches deliberately over-sample first pages, 200 against 650 interior pages,
because `Title` and `Authors` occur nowhere else. Four batches were annotated
to build `round_final`.

### 4. Assemble a round and split

Place images in `training_dataset/<round>/images/`, labels in `labels/`, copy a
`data.yaml` and `classes.txt` from an existing round, then:

```bash
python -m doclayout_ft.data.split_dataset --round <round>
```

## Annotation guidance

Learned from where this dataset went wrong.

**Box tightly and box consistently.** Consistency matters more than any single
judgement call. The `Page-footer` class here scores 0.36 mAP50-95 against 0.75
overall, while its precision and recall sit above 0.9. The model finds every
footer and cannot agree with the labels on where its edges are, because the
labels themselves do not agree with each other. That is an annotation defect,
and no amount of training fixes it.

**Decide the edge cases once, in writing.** Does `Page-footer` include the
horizontal rule above it? Does `Authors` include affiliation footnotes? Does a
multi-line caption include its figure number? Whatever the answer, the same
answer every time is what the model can learn.

**One box per logical region.** A paragraph split across a column break is two
`Text` boxes, not one spanning the gap.

**Do not annotate what you will not use.** Every class costs annotation time
and dilutes the rest.

| `round_final` | 850 (632 / 130 / 88) | Paper-level, seed 42 | **Yes** |

### Why round_03 is void

Its `data.yaml` pointed `train:` and `val:` at the same image directory. The
model was validated on its own training data, so every metric from that period
measured memorisation. Numbers from `round_03` and earlier cannot be compared
against `round_final` ones, and are kept only to make the lineage legible.

`round_final` splits by paper: all pages of a paper land in the same split.
Pages of one paper share a template, so a page-level split leaks layout across
the boundary and inflates validation the same way, just less obviously.
